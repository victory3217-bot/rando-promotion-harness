# 공통 Harness 규칙 (PLAYBOOK)

이 문서는 이 저장소의 **공통 규칙 SSOT**다. Claude Code와 GPT/Codex 어느 플랫폼에서 실행되든
동일하게 적용되는 규칙은 이 파일에만 존재한다. 플랫폼별 진입점(`CLAUDE.md`, `AGENTS.md`)은 이
문서를 참조만 하며 내용을 복제하지 않는다.

이 저장소는 소규모 사업자의 홍보문구·예약안내·상품소개·이미지 제작을 실제로 수행하는 작업공간이다.
강의/교육용이 아니라 **실제 게시·발송에 쓰이는 콘텐츠**를 만드는 것이 목적이다.

## Input 원칙

이 Harness는 고정된 상품 정보 파일이나 체크리스트를 사용하지 않는다. **이번 작업의 사실 원본은
사용자가 현재 대화에서 서술형으로 제공한 상품·서비스 설명이다.**

1. 사용자가 이번 대화에서 명시적으로 말한 사실만 사용한다.
2. 사용자가 말하지 않은 가격·일정·환불조건·상품조건 등은 추측해서 채우지 않는다.
3. 누락된 정보가 있어도 콘텐츠가 성립하면 질문하지 않고 생략한다.
4. 누락된 정보 때문에 콘텐츠 자체가 성립하지 않을 때만 사용자에게 질문한다.
5. 한 대화에 여러 상품·서비스가 언급되면, 이번 요청의 대상 상품을 먼저 명확히 하고 그 상품의
   서술형 설명만 사실 원본으로 사용한다. 다른 상품에서 나온 사실을 섞지 않는다.
6. 고정된 상품 스키마나 체크리스트(예: 26개 항목 Form)를 새로 만들거나 사용하지 않는다. 요청된
   콘텐츠 유형에 실제로 필요한 사실만 그때그때 확인한다.
7. 여러 항목을 질문해야 하면 한 번에 묶어서 질문한다.
8. 질문했는데 사용자가 모른다고 답하면, 결과물에 꼭 필요한 항목일 때만 내부적으로 `[확인필요]`로
   남긴다. 필요 없는 항목은 묻지 않고 넘어간다.

## 정보 우선순위

요청을 처리할 때 아래 순서로 정보를 신뢰한다. 충돌하면 더 최근에 확인된 사업 사실을 우선하고,
그래도 불확실하면 사용자에게 질문하거나 `[확인필요]`로 남긴다.

1. 이번 대화에서 사용자가 서술형으로 제공한, 이번 요청 대상 상품·서비스에 대한 설명 — 이번
   작업의 사실 SSOT
2. `skills/*/SKILL.md` — 요청 채널/문서 유형의 작성 형식과 표현 규칙
3. `knowledge/personal-profile.md` — 운영자(사용자)의 말투와 답변 선호

## 절대 규칙 (Governance)

- 이번 대화에서 사용자가 말하지 않은 가격·일정·환불·상품조건을 만들지 않는다. 콘텐츠 성립에
  반드시 필요한데 확인할 수 없을 때만 `[확인필요]`로 남기고, 필요하지 않으면 언급하지 않고
  생략한다.
- 고객 이름·전화번호·주소·예약내역 등 개인정보를 요구하거나 프롬프트에 넣지 않는다.
- 과장·최상급·근거 없는 효능 표현을 쓰지 않는다 (예: "특별한 경험", "잊지 못할 추억", "최고", "유일한", "힐링").
- 채널마다 목적을 구분한다.
  - SNS(블로그/페이스북/인스타그램): 아직 모르는 고객의 관심과 문의 유도
  - 상품소개: 구매를 고민하는 고객의 판단 지원
  - 예약안내: 이미 예약한 고객의 방문 준비 지원
- 긴 원본을 먼저 만든 뒤 채널에 맞게 재가공한다. 채널별로 처음부터 따로 쓰지 않는다.
- 이미지 생성 시 실제 사진이 있으면 실제 사진을 우선하고, AI 이미지는 보조·초안으로만 쓴다.
- 이번 대화의 서술형 설명이나 `knowledge/personal-profile.md`에 없는 항목을 임의로 채우지 않는다.

### `[확인필요]` 처리 원칙

`[확인필요]`는 "언급되지 않은 정보"에 자동으로 붙는 표시가 아니다. 아래 순서로만 판단한다.

1. 사용자가 말한 정보는 확인된 사실로 사용한다.
2. 사용자가 말하지 않았지만 콘텐츠 작성에 필요하지 않은 정보는 질문하지 않고, `[확인필요]`로도
   남기지 않고 완전히 생략한다.
3. 콘텐츠 성립에 반드시 필요한데(그 정보 없이는 문안이 성립하지 않는데) 사용자가 말하지 않은
   정보는 사용자에게 질문한다.
4. 질문했는데도 사용자가 확인해줄 수 없는 경우에만 `[확인필요]`로 내부 관리한다. `[확인필요]`
   목록에는 이렇게 3~4단계를 거친 항목만 들어간다 — 애초에 필요하지 않아 묻지 않은 정보는
   이 목록에 들어가지 않는다.
5. `[확인필요]` 항목은 외부 고객에게 보여지는 **최종 게시 문안에는 기본적으로 노출하지 않는다.**
   - 그 정보 없이도 문안 작성이 가능하면 최종 문안에서는 해당 내용을 생략한다.
   - 사용자가 명시적으로 "미정이라고 표시해라", "추후 공지라고 써라"처럼 요청한 경우에만
     최종 문안에 미확정 상태를 표시한다.

## 채널 공통 사실검증 절차 (모든 결과물에 항상 적용)

어떤 채널·문서 유형이든 결과물을 낼 때는 **항상** 아래 순서로 마무리한다. 이 절차는 특정 Skill에
속하지 않고 이 파일을 통해 항상 적용된다.

1. 결과물 안의 가격·일정·환불·상품조건·연락처 등 사실 항목을 이번 대화에서 사용자가 말한 서술형
   설명과 하나씩 대조한다.
2. 최종 문안에 사용자가 말하지 않은 사실이 들어가지 않았는지 확인한다. `[확인필요]` 목록에 있는
   항목(콘텐츠 성립에 필요해서 질문했지만 끝내 확인되지 않은 항목)이 최종 문안에 그대로
   노출되지 않았는지도 확인한다 — 사용자가 명시적으로 미확정 표시를 요청한 경우만 예외로
   허용한다. 콘텐츠에 필요하지 않아 애초에 질문하지 않은 정보는 `[확인필요]` 목록에도 없어야
   하며, 최종 문안에도 당연히 없어야 한다.
3. 고객 개인정보가 포함되지 않았는지 확인한다.
4. 과장·최상급·근거 없는 효능 표현이 없는지 확인한다.
5. 한 대화에 여러 상품이 언급된 경우, 이번 요청 대상이 아닌 다른 상품의 사실이 섞여 들어가지
   않았는지 확인한다.
6. 결과물 마지막에 다음 형식을 항상 붙인다.
   1. 최종 문안
   2. `[확인필요]` 항목 목록
   3. 사실확인 체크 (위 1~5 항목을 통과했는지)
   4. 다음 수정 제안 1~3개

## 기본 작업 흐름

1. 사용자의 서술형 설명에서 이번 요청의 대상 상품·서비스를 확정한다. 대화에 여러 상품이
   언급되어 있다면 그중 이번 요청과 관련된 설명만 사실 원본으로 삼는다. 상품 설명 자체가
   아직 없으면 먼저 요청해서 받는다.
2. `knowledge/personal-profile.md`를 읽어 말투·형식 선호를 확인한다.
3. 요청된 채널/문서 유형을 판단하고 맞는 `skills/*/SKILL.md`를 정한다
   (`blog-promotion`, `facebook-promotion`, `instagram-promotion`, `reservation-message`, `product-description`).
4. 그 콘텐츠 유형에 실제로 필요한 사실 중 사용자가 아직 말하지 않은 항목이 있는지 판단한다.
   누락되어도 콘텐츠가 성립하면 질문하지 않고 생략하며, 성립하지 않을 때만 한 번에 묶어서 질문한다.
5. 초안을 만든다. 사용자가 말하지 않은 사실은 만들지 않는다.
6. 위 "채널 공통 사실검증 절차"를 적용한다.
7. 최종 결과물 + 확인필요 항목 + 사실확인 체크 + 다음 제안을 함께 제시한다.

콘텐츠 제작 요청의 실행 주체는 `agents/promotion-agent.md`에 정의되어 있다.
